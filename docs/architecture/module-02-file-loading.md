# File loading and detection

## Contract and boundaries

`src/types/files.ts` defines the typed `FileDescriptor`, detection sources, warnings and error codes. `FileLoader` is the only frontend loading service. React renders metadata and detection evidence only. No contents, images, tables or archive members are rendered.

The native adapter invokes `load_file`; `select_path` opens a native dialog and grants a **pinned handle** for the selected regular file. Native drag/drop grants handles on a worker, then emits `prism://files-dropped`. Publishing after authorization avoids the event/read race. Folder selection grants no recursive access. An event forged by frontend code cannot create a backend grant.

App command permissions are generated by `tauri-build::AppManifest` and granted only to the main window. The plugin's broad JavaScript dialog access is no longer required. Browser mode never invokes native read commands and never invents an absolute path.

## Paths and handles

Paths must be absolute, canonicalizable regular files; NUL and Windows device / GLOBALROOT paths are rejected. OS permission errors are mapped to typed user-facing errors with detailed OS errors retained in native logs. Symlinks resolve to their canonical target at selection. A retargeted symlink resolves to a different ungranted target and is denied. Inspection uses the already granted handle, so replacing a path cannot grant arbitrary replacement content. In-place modifications remain possible and size/mtime changes during inspection generate `FILE_CHANGED`.

The grant cache holds at most 128 handles. Inspection is serialized around cloned handles because clones can share an OS cursor. Drop batches inspect at most 32 inputs, sequentially. No path API allows the frontend to self-authorize a read.

## Rules

1. Strong signatures win over suffixes: PNG, JPEG, GIF, PDF, RIFF+WEBP, ZIP, SQLite and AVIF brand.
2. For readable whole samples, parse JSON object/array content or structurally parse XML; SVG roots are resolved before generic XML. DTDs are not sniffed.
3. Browser MIME hints may support text candidates, below validated content. Unsupported binary MIME hints cannot override missing magic evidence.
4. Case-insensitive suffix aliases identify source code, Markdown and config candidates. Basename and shebang rules supply language hints.
5. CSV/TSV require suffix/MIME support; quote-aware delimiter consistency raises confidence. YAML/TOML are extension-based candidates; ordinary prose is never inferred as YAML.
6. Unknown readable samples become `text`; unknown binary samples become `unknown` with warnings.

Native MIME is a semantic MIME mapping of the resolved type, not a second independent observation. It therefore does not manufacture a `mime` detection source. Browser `File.type` is a hint and may itself originate from the suffix; it is not proof of file validity.

JSON/XML/SVG content recognition is limited to whole files up to 64KB. Larger files retain text/extension evidence and warnings instead of full parsing. Text classification combines BOMs, strict UTF decoding, NUL rejection and a 2% disallowed-control threshold; valid decoding alone is not sufficient. UTF-8 sequence cutoffs are accepted only for incomplete samples. No legacy encoding is guessed.

ZIP classification reads a bounded tail and central directory only. It recognizes XLSX when metadata contains both `[Content_Types].xml` and an `xl/` member. ZIP64/multi-disk/oversized directories remain ZIP with a limit warning. Full OOXML schema validation belongs to a later module.

## Identification versus validity

Confidence describes evidence for a type. A strong PNG signature can yield PNG even when the file is truncated; obvious sample/header inconsistencies generate `CORRUPTED_SIGNATURE`. This module never labels a file fully valid. Malformed `.json` retains its low-confidence extension candidate with `CONTENT_UNVERIFIED`, while malformed braces in `.txt` remain text.

## Tests

Rust tests exercise the real granted-handle loader, metadata, signature rules, adversarial inputs, concurrent reads, limits and error boundaries. Browser unit tests mirror the fixture corpus; real-browser file-input checks verify the actual File API. Inspector tests cover both modes, mismatch presentation, typed errors, drop dispatch, folder non-recursion and stale-result suppression. Sample generator and fixtures live in `tests/fixtures/files`.

Tauri APIs: [native dialog builder](https://docs.rs/tauri-plugin-dialog/latest/tauri_plugin_dialog/struct.FileDialogBuilder.html), [window drag/drop events](https://docs.rs/tauri/latest/tauri/enum.WindowEvent.html). These APIs are confined to adapters and native commands.
