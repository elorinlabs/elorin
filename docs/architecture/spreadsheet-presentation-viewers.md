# Module 10 — Spreadsheet / Presentation

The two lazy plugins use FileDescriptor → ViewerRegistry → ViewerHost. The shell does not dispatch on Office extensions. Detection exists in both browser and Rust; ZIP subtype detection uses the central directory and OpenDocument mimetype. Legacy CFB files route to an explicit limited preview. No new native permission or command is needed.

OfficePackage wraps the existing Module 09 ZIP validation/inflation worker and safeXml. It centralizes relative relationships, package metadata, macro/object inventory, sanitized embedded image URLs and cleanup. Module 09 now reuses this relationship/image layer. Its 64-image allowance remains intact; Module 10 uses a 32-entry image LRU. Module 08 SVG sanitation and raster dimension checks remain the image boundary. Neither relationships nor image paths initiate remote requests.

Spreadsheet models store Map<address, Cell>, preserving raw XML values separately from displayed values, types, formula strings and styles. Workbook metadata precedes active sheet parsing; subsequent sheets load on request. Worksheet XML uses a namespace-aware streaming parser with cooperative cancellation. Three parsed sheets are cached, with a 200k inactive-cell budget. SparseAxis stores only row/column overrides and computes offsets by binary search; it does not allocate logical worksheet dimensions. CSV shares the generic range/intersection helpers; workbook data never passes through CsvDocumentModel or CSV serialization. Browser scroll extents remain below Chromium's height ceiling for Excel's maximum rows at the default 28px height.

SSF interprets saved number formats and date epochs. It is not a formula engine. All formulas, shared-formula markers, names, connections and DDE strings remain inert. Only saved cached results appear; absent caches say Result unavailable. Styles show stored formatting; conditional formatting rules are counted but never evaluated.

Presentation models retain package paths, native slide dimensions, geometry, text runs, tables and inert object placeholders. Current slides are loaded lazily, five parsed slides are retained, and the current slide is pinned while the virtual thumbnail rail loads nearby previews. Geometry is fitted proportionally into the available stage. Masters/layouts provide static backgrounds, shapes and placeholder geometry where supported. The default thumbnail rail is collapsed. Notes, comments, search, internal links and fullscreen are read-only.

Limits are deliberate: Office package 128 MiB compressed / 256 MiB expanded, 2048 entries, 96 MiB per entry/streamed worksheet, six million XML elements, depth 64, two million stored cells per XLSX worksheet. Non-streamed metadata XML retains Module 09's 8 MiB / 100k node bound. ODS repeated materialized values are capped at 200k. Malformed, encrypted, unsupported legacy and over-budget inputs produce a bounded explanation, never partial fabricated values.

This is a static preview renderer. It does not promise Office layout equivalence: complex theme inheritance, font substitution, gradients, advanced charts, SmartArt layout, pivot engines, conditional rules, unsupported vector commands, ODF styling and binary XLS/PPT require an external application. Animations/media/program actions/macros/embedded objects never execute. Safe external HTTP(S) links require an explicit user confirmation and use the existing system browser service; unsafe schemes have no execution path.
